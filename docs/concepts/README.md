# Core concepts

These four pages give you the background you need before the
specifications make sense. They explain things rather than require them,
and you don't need to know anything before you start. Read them in order;
each one takes about ten minutes.

| # | Read | You will know |
| --- | --- | --- |
| 1 | [What is an EMIS](emis.md) | What an education management information system is, who relies on it, and which part of it this blueprint covers |
| 2 | [The EMIS domain](domain.md) | What a domain model is, why we use one, and the main things an EMIS records |
| 3 | [Data in an EMIS](data.md) | The kinds of data an EMIS holds, and five ideas about handling them that the rest of the blueprint builds on |
| 4 | [Terminology](terminology.md) | The handful of classifications and terms you need to read the specifications, such as sensitivity tiers, layers, clauses and roles |

When you've read them, go on to the
[specifications](../specifications/README.md), starting with the
principles.
