## Summary

Make every language a first language, from the start. The documentation
is written in English and translated through gettext PO files, built into
a multilingual website that supports right-to-left scripts. A new
principle (P22) and a new clause (CAP-REFERENCE.9, labels for codes in
every official language) carry the same idea into the platform itself.
French, Spanish and Arabic are the first languages, with the core
concepts translated.

## Motivation

Education authorities often work in more than one official language, and
the people an EMIS serves should not need a second language to read their
own data or the rules that govern it. Adding languages later is costly:
pages written without translation in mind, interfaces with hard-coded
text and code lists with one label each all have to be reworked.
Translations kept as copies of pages drift silently from their source.

## Specification

- **Principle P22, "Every language is a first language":** text is
  written once and translated through translation files; every coded
  value has a label in each official language; right-to-left scripts are
  laid out right to left; a translation that has fallen behind is not
  shown.
- **CAP-REFERENCE.9 (MUST):** every code in a code list has a label in
  each official language the authority declares, tagged with BCP 47;
  where a label is missing, interfaces fall back to a declared default
  language, never to the bare code.
- **Documentation:** English Markdown is the only source.
  `scripts/l10n.py` extracts templates with Translate Toolkit, merges
  them into one PO file per page and language with GNU gettext, and
  rebuilds translated pages for the website. A page is published in a
  language only when fully translated; otherwise readers see English.
  Code blocks, diagrams and front matter are never offered for
  translation. `just check` fails when templates or PO files are stale.
- **Website:** one site per language, menus and notes labelled from
  Hugo interface strings, right-to-left layout for Arabic, and a note on
  each translation not yet reviewed by a native speaker.
- **Languages:** English (source), French, Spanish and Arabic, listed in
  `l10n/languages.toml`. Decision records and proposals stay in English.

## Rationale

- **PO files rather than copied pages.** A PO file records each string's
  source next to its translation and flags the strings whose source
  changed, so a stale translation is detected, not discovered. Copied
  pages (as some large documentation projects use) are simpler to start
  but can fall behind without anyone noticing.
- **Translate Toolkit and gettext.** Both are open source and long
  established; Translate Toolkit is also how the Weblate translation
  platform reads Markdown, so a hosted workflow can be added later with
  no change of format.
- **Unpublished until complete.** A page mixing two languages is harder
  to read than either, and a partly updated translation can contradict
  its source. Falling back to English is the honest default.
- **Arabic among the first languages.** It is written right to left, so
  it tests the layout from the start rather than after it has set.

## Compatibility

Catalogue 0.5.0, a minor release: before 1.0.0, a new MUST clause is
allowed in a minor version. Both reference bindings list CAP-REFERENCE.9
as `planned`. Documentation pages move nowhere; editing a translated page
now requires `just l10n-update` in the same change.

## Path to active

- **Acceptance criteria:** catalogue 0.5.0 released; `just check`
  verifies the translation files; the website builds in all four
  languages with the core concepts translated; a native speaker has
  reviewed at least one language.
- **Implementation plan:** the maintainers make the change in one
  release; native-speaker review of French, Spanish and Arabic is sought
  through the contributing process.

## Privacy and safeguarding

Positive. Guardians and learners can read about their data, and the
rules protecting it, in their own language. Translated labels for codes
reduce the risk of a code being misread at the point of entry.

## Security

None. Translation files are text, reviewed like any other change, and
cannot alter code blocks, diagrams or page headers.
